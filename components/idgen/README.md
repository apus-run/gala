# idgen


| 模块 | 职责 |
| --- | --- |
| `pkg/id` | 本地 Sonyflake、短码编码；机器号由应用部署配置 |
| `components/idgen/redis_gen` | Redis 原子分配单个或批量 ID；进程可以共享 server ID |

不引入全局生成器、按 IP 识别实例、`INCR % N` 循环分配机器号或故障时默认
机器号 0。Redis 版本的 server ID 是数字分区，不是需要独占租约的进程身份。

## 使用

```go
// 显式管理操作：只为从未使用过的数字分区执行一次。
if err := redis_gen.InitializeState(ctx, client, 1, 0, 0); err != nil {
    return err
}

// 正常启动，不自动初始化或修复历史状态。
g, err := redis_gen.NewIDGenerator(client, []int64{1})
if err != nil { return err }
ids, err := g.GenMultiIDs(ctx, 1000)
```

导入 `github.com/apus-run/gala/components/idgen/redis_gen`。
客户端由调用者管理。构造时复制 server ID 切片，实例可并发使用。
相同数字 ID 域中的所有生产者必须使用同一 Redis 数据库和分配状态。

每个非空批次仅执行一次 Lua 脚本，原子保存并推进
`id_generator:v2:<server>` 的 `ms`、`seq`，不设置 TTL。
使用 Redis TIME，取墙上时间与已分配进度中的较大位置；序列耗尽时向下一
毫秒进位。批次内以及同分区的分配顺序递增，并发请求的完成顺序不保证递增。
完整 64 位 ID 在 Go 中组装，避免 Lua 浮点精度影响。

## 边界与错误

- 数字布局保留为 秒 32 位、毫秒 10 位、序列 8 位、server 14 位。
- server ID 范围为 `[0, 16383]`，批量数量为 `[0, 65536]`。
- 数量为 0 返回空切片，不访问 Redis。负数或超大批次返回错误。
- 状态缺失返回 `ErrStateMissing`，不自动重建；错误类型、残缺、越界或
  带 TTL 的分配状态也拒绝发号。
- Redis 不可用时返回错误，没有本地降级生成器。
- 失败或取消不返回部分批次，但可能已消耗区间；重试分配新区间，不能回收旧区间。
- 时间为逻辑分配时间，负载较大时可能领先实际时间，不作为精确事件时间。
- 保留正 int64 范围：逻辑 Unix 秒超过 2147483647 时返回错误，即
  2038-01-19 03:14:07 UTC 后不能继续使用该布局，不能静默溢出。

## 唯一性保证的前提

**时钟回拨与状态回退是两回事。** 分配进度仍在 Redis 时，时钟回拨、应用
重建以及响应丢失后的重试不会重复分配区间。进度键缺失是可检测的，因此拒绝
发号。格式合法的旧快照与当前状态无法仅靠同一个 Redis 可靠区分。

因此，本实现的唯一性以 Redis 已确认的分配进度不丢失、不回退为前提。
使用持久化、禁止驱逐分配键，并选择符合该前提的故障恢复策略；Lua 原子性
不等于复制或故障切换不会丢写入。不承诺 Redis 历史恢复到旧版本后仍能自动
证明 ID 唯一，也不为此引入 PostgreSQL 或另一套协调协议。

恢复时停止旧写入者，使用可验证的最后分配位置初始化缺失状态；初始化不会
覆盖已有键。不能证明历史最高位置时，不应重新使用同一数字分区，应采用从未
使用过的 server ID 或另外的数字 ID 域。低位恢复种子可能造成重复。
不同 Redis 数据库、独立部署或本地 Sonyflake 的 ID 不保证彼此不重叠。

旧版按毫秒过期的计数键与 v2 状态不互通：迁移必须停旧写入者并初始化覆盖全部
历史分配的进度，不能与旧实现混跑。初始化不是每次启动的默认动作。

## 验证

在该模块运行 `go test -race ./...`，覆盖参数与取消、并发分配、序列及跨秒
边界、时钟回拨、应用重建、状态缺失/损坏、响应丢失和显式初始化不重置进度。
这些测试使用 miniredis，不代替生产 Redis 持久化与故障切换验证。

`pkg/id` 保留 `NewSonyflakeChecked`、`NextIDContext` 和 `NewCodeChecked`
改进。它们不依赖 Redis；上游 Sonyflake 等待不能中途取消，短码也只在已声明
容量内保证唯一编码，详见该模块 README。

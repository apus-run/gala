# hook

Generic, concurrent-safe event hooks with middleware-style chain semantics.
A handler must call `event.Next()` for the chain to proceed; the value a
handler returns is simply surfaced to the `Trigger` caller — an error never
unwinds the chain, and not calling `Next()` stops it silently. Ported from
pocketbase's `tools/hook`.

## Usage

```go
type CustomEvent struct {
    hook.Event
    SomeField int
}

h := hook.Hook[*CustomEvent]{}

h.Bind(&hook.Handler[*CustomEvent]{
    Priority: -1, // runs before the default 0-priority handlers
    Func: func(e *CustomEvent) error {
        e.SomeField++
        return e.Next() // omit to stop the rest of the chain
    },
})

err := h.Trigger(&CustomEvent{SomeField: 123},
    // optional one-off funcs, appended to this trigger only
    func(e *CustomEvent) error { return e.Next() },
)
```

Binding with an already used `Id` replaces that handler; `Unbind(ids...)`
removes by id; autogenerated ids come from a process-wide counter.

`NewTaggedHook(base, "admin")` wraps a `Hook` so the handlers bound through
it fire only for events whose `Tags()` overlap with the given tags — an
empty tag list matches all events (see [tagged.go](tagged.go)).

Runnable examples:

- [examples/publish](examples/publish) — interceptor style: validation →
  filter → publish → audit, a handler can stop the chain by not calling
  `Next()`.
- [examples/email](examples/email) — observer style: independent listeners
  that never stop the chain, runtime Unbind, hot-swapping a handler by
  re-binding its Id, and a listener that reports its own error without
  affecting the others.

## Known limits

- **Snapshot semantics.** A running `Trigger` is unaffected by concurrent
  `Bind`/`Unbind` — it executes an immutable snapshot. The same event
  instance can be triggered again, even re-entrantly from inside a handler.
- **Stopping is Next-shaped, not error-shaped.** A returned error does not
  halt the chain — skipping the remaining handlers means not calling `Next()`.

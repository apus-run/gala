# 测试清单

测试可观察的配置行为和原库契约，不比较任意 Option 的身份。以下项目按目标包真实能力选择；没有 map 或读取 API 的库不需要为测试而新增它们。

## 必须覆盖的核心行为

| 场景 | 验收点 |
| --- | --- |
| `DefaultOptions()` 多次调用 | 配置对象与本应独立的可变默认数据互不污染 |
| `NewOptions()` 无参数 | 默认值正确且通过已有必要校验 |
| 顺序应用 | 设置顺序可观察；不得排序、并行或隐式去重 |
| 重复标量选项 | 原本覆盖的继续后者生效 |
| 追加/合并选项 | 保留原追加顺序与键冲突规则，不改成统一覆盖 |
| 显式零值 | 合法的 0、false、空字符串不会被默认值覆盖 |
| 多次 `Apply` | 不重置之前未涉及的字段；空参数不改变有效配置 |
| `OptionFunc` | 被调用且仅按循环顺序执行 |
| 最终校验 | 最终状态合法才成功；`NewOptions` 不提前校验 |
| 校验纯度 | Validate 不设置默认值、不修改参数、不创建资源 |
| 错误身份 | 保持原 `errors.Is/As`、错误类型及已承诺的传播行为 |
| API 适配 | 包外自定义函数通过导出 OptionFunc 正常组合选项 |

如果存在跨字段关系，测试“一个中间状态不合法，但全部应用后的最终状态合法”。不要只用独立字段测试代替跨字段测试。

## 存在可变数据时

- 在创建 Option 后修改调用方原始 map/slice，按已选择的捕获契约验证结果。
- 同一 Option 应用于两个配置，修改其中一个不污染另一个，前提是约定独立所有权。
- Getter 返回的容器或配置快照被修改，不影响内部本应只读的状态。
- 通过 OptionFunc 保留构造时收到的配置指针，构造完成后修改它，不影响承诺独立的组件。
- 嵌套容器按实际层级测试；服务依赖的有意共享按相反方向测试，不盲目要求复制。

## 类型与 nil 边界

不把 nil Option、nil OptionFunc 或 nil 接收者作为目标 API 支持的正常输入，不编写迫使 Apply 静默跳过或返回 error 的测试。

无需增加“所有无效输入统一 panic”的契约测试，因为简单循环不承诺统一结果。若原库本来支持 nil，先在迁移说明记录兼容性冲突，而非直接删除相关回归测试。

实际需要使用具体结构体选项时，验证它可与函数适配选项混用；不要求所有包为此增加无用的生产类型。

## 构造与资源阶段

以原库 mock、fake 或测试资源检查：配置未通过校验时不启动资源；初始化失败时保留既有清理与错误传播。不为了这个模式新增资源管理框架。

示例没有真实网络或文件资源，因此它的测试不能替代目标库的资源生命周期验证。

## 执行要求

先在修改前尝试记录基线，迁移后运行相同命令。若依赖下载、平台、服务或测试本身存在问题，分别说明，不改无关测试凑绿色结果。

```sh
gofmt -w <实际修改的Go文件>
go test ./...
go vet ./...
go test -race -count=1 ./...
```

依据仓库约束运行指定 build tags、生成检查、最低受支持 Go 版本和平台矩阵。若存在多个 module，在各 module 中执行；不要声称一次 `./...` 会遍历所有嵌套 module。

测试最小 Go 版本必须真的使用相应工具链运行，仅在 `go.mod` 中声明版本不构成测试证据。

## 交付记录模板

```text
检查 | 目录/模块 | 实际命令 | 状态 | 说明
格式 | ...       | ...      | 通过/失败/未执行 | ...
单测 | ...       | ...      | 通过/失败/未执行 | ...
Vet  | ...       | ...      | 通过/失败/未执行 | ...
竞态 | ...       | ...      | 通过/失败/未执行 | ...
兼容 | ...       | ...      | 通过/部分/未检查 | ...
```

竞态检测只验证覆盖到的执行路径，不宣称对所有业务负载或第三方 Option 的并发安全证明。

# Skill 执行评估场景

用于人工或 Agent 评估，不是自动修改脚本。把场景与目标包实际代码一起提供，检查结果而不是只检查是否出现接口声明。本次随包 Go 测试通过不代表以下 Agent 场景已自动跑过。

## 场景 A：普通函数选项

输入：有 `type Option func(*Options)`、timeout/retries、重复默认值和多个应用循环。要求按本 Skill 迁移，允许内部 API 同步修改。

应得到：接口 + 导出函数适配器；默认值一个来源；NewOptions 复用 Apply；Apply 仅有循环；公开 With 返回 Option；行为测试和兼容性说明。

不应得到：泛型公共包、Builder、nil 防御、一个选项一个结构体或额外资源抽象。

## 场景 B：追加 Hooks

输入：`WithHooks(a)` 后再 `WithHooks(b)` 原本追加；还存在 `WithLabels` 合并策略。

应得到：原顺序、追加与键冲突规则保留，并有测试。不得因为标量示例是覆盖，就把所有选项统一为最后一个生效。

## 场景 C：带错误的解析选项

输入：某 Option 解析输入并可能返回错误，原流程首错停止；构造函数已经被其它模块使用。

应得到：先说明最终校验与首错停止不等价，保留错误身份和构造契约；仅在授权后更改错误时机。冲突时做安全部分并明确未完成项。

不应得到：忽略 error、panic 代替普通错误、Options.err 隐藏缓存、擅自改构造签名。

## 场景 D：公开配置用于 YAML 解码

输入：调用方解码到带导出字段的 Options，并通过结构体字面量创建配置；不允许破坏外部接口。

应得到：识别私有化冲突，核对输入层与配置层边界；在未授权时不静默改字段，不宣称完整迁移或完全兼容。

## 场景 E：可变输入与重复使用

输入：同一个带 map/slice 的 Option 复用于两个实例，要求配置独立；构造对象可通过回调被保留。

应得到：按已约定捕获时点复制输入及每次应用数据，隔离运行时状态；对嵌套引用有说明。不得仅复制外层 Options 就宣称完全独立。

## 场景 F：历史 nil 支持

输入：旧 Apply 明确忽略 nil，且有公开文档与消费者依赖；用户未允许破坏性变更。

应得到：标记与目标极简 Apply 的契约冲突，按版本策略处理，不删除回归测试凑通过，也不往目标 Apply 重新加防御。

## 场景 G：接口型 Option 的比较

输入：迁移后使用 `map[Option]bool` 去重，部分选项由 OptionFunc 实现。

应得到：指出不可比较动态类型风险；保持顺序应用，不按任意选项身份去重；测试结果而不是 `==`。

## 场景 H：工具不可用或多模块

输入：Go 工具链缺失，或仓库有三个 module，根目录测试只覆盖其中之一。

应得到：报告真实检查范围和未执行项；不能写全部测试通过；不下载/升级工具链或依赖来绕过用户约束。

## 总体验收

通过需同时满足目标结构、原业务语义、兼容性、数据所有权、最小差异和真实验证六项。仅仅生成漂亮的 options.go 不算完成迁移。
